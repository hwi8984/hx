# web.md — 결과물이 웹 서비스일 때 (step 절차의 부록. 과제가 "실행되는 서비스·화면·대시보드"를 요구하면 v0 전에 읽는다)

## 1. 서버 규칙 (어기면 미리보기가 안 열린다)
- 바인딩은 **`0.0.0.0`**. `localhost`·`127.0.0.1`에 띄우면 웹 IDE의 Browser 탭에서 안 보인다.
- 시작하면 터미널에 **실제 포트를 한 줄로** 찍는다: `서버: 0.0.0.0:8000 · PORT=8000 · 브라우저: Browser 탭 PORT 칸에 8000`.
- 포트는 `--port` 옵션으로 바꿀 수 있게. 기본 포트가 사용 중이면 다음 포트(8001, 8080, 8765…)로 띄우고 바뀐 포트를 다시 찍는다. 조용히 다른 포트로 가지 않는다.
- **표준 라이브러리로 쓴다**(`http.server` + `urllib`). Flask·FastAPI 같은 패키지는 설치돼 있다고 가정하지 않는다. 있어도 쓰지 않는다 — 검증자와 채점자 환경에 없을 수 있다.
- 화면 자산(HTML·CSS·JS)은 전부 로컬 파일로. 외부 CDN·웹폰트·외부 API 요청 0건(사내망·오프라인 요구가 흔하고, 시험 환경도 외부 접속이 막혀 있다).
- 결과 데이터는 **JSON API 한 개**(예: `/api/result`)로도 내보낸다. 화면은 그 JSON을 그려 보여 준다. 검증자는 화면 대신 이 JSON을 다시 센다.
- 요청마다 입력 파일을 **다시 읽어** 계산한다(파일이 바뀌면 새로고침만으로 반영). 서버를 다시 켜야 반영되는 구조는 피한다.
- 입력이 없거나 깨졌으면 빈 화면 대신 **오류 문장**을 화면과 JSON에 띄운다(422 등). 조용히 0건으로 보이지 않게.
- 결과 파일: 검토 때 API 응답 한 벌을 `out/latest/result.json`으로 저장해 둔다(`HXCMD check`는 out/latest가 비어 있으면 문제로 본다).

## 2. 터미널 운영
- 서버는 **새 터미널 탭**에서 띄운다(`+`). 그 탭은 시험 끝까지 닫지 않는다. 다른 명령은 다른 탭에서.
- 서버 탭에서 `Ctrl+C`를 치면 서버가 꺼진다. 사용자에게도 "서버 탭에서는 아무것도 치지 마세요"라고 말한다.
- 코드를 고쳤으면 서버 탭에서 `Ctrl+C` → 같은 명령으로 다시 띄운다(자동 재시작 기능을 만들지 않는다).
- 서버가 떠 있는지 확인: 다른 탭에서 `python3 -c "import urllib.request;print(urllib.request.urlopen('http://127.0.0.1:8000/api/result').status)"` → `200`.

## 3. 사용자에게 안내하는 문구 (서버를 띄울 때마다 그대로)
```
서버가 0.0.0.0:8000 에서 돌고 있습니다.
왼쪽 Browser 탭 → PORT 칸에 8000 → URL 경로는 / → 새로고침(원형 화살표).
화면이 보이면 설비(행)를 눌러 근거가 펼쳐지는지 확인해 주세요.
안 보이면 알려 주세요 — 포트·바인딩·경로 순서로 제가 확인합니다.
```
Browser 탭의 PORT 칸은 **기본값 3000**으로 채워져 있다. 서버를 3000에 띄우지 않았으면 "포트 3000에 아직 응답하는 서버가 없어요"가 뜬다 — 오류가 아니라 PORT 칸을 실제 포트로 바꾸라는 뜻이다. 미리보기 주소가 `*.e2b.app`으로 보이는 것은 정상(샌드박스 주소). 사용자는 그 주소를 외울 필요가 없다.

## 4. 안 열릴 때 점검 순서 (위에서부터 하나씩)
1. 서버 탭 터미널에 오류가 있나(경로·모듈·포트 충돌).
2. 터미널에 찍힌 **실제 포트**와 Browser 탭 PORT 칸이 같은가.
3. 바인딩이 `0.0.0.0`인가(코드와 출력 둘 다).
4. URL 경로가 `/`인가(정적 파일 경로를 직접 치지 않았나).
5. 새로고침을 눌렀나. 그래도 안 되면 서버를 껐다 다시 켠다.
6. 다른 탭에서 `urllib`로 200이 나오는데 Browser만 안 되면 → 사용자에게 "Browser 탭을 닫았다 다시 열어 PORT를 다시 입력"하라고 안내하고, 그래도 안 되면 "문제 신고"(Cofa Helper).

## 5. 검증 (브라우저 자동화 없이)
- 테스트는 서버를 **임시 포트**로 띄워 `urllib`로 응답 상태·JSON 값을 확인한다(표준 unittest). node·Chrome·Playwright가 있다고 가정하지 않는다.
- 화면 확인은 사용자가 Browser 탭에서 직접 누른다. 그 결과("행을 누르니 근거가 펼쳐졌다")를 WORKLOG에 한 문장으로 남긴다.
- verifier는 `/api/result` JSON을 받아 원본과 대조한다. README "확인 방법"에 그 JSON 경로를 적어 둔다.

## 6. README "바로 실행" 형식 (웹일 때)
```
python3 src/server.py            # 0.0.0.0:8000 · PORT=8000 이 찍히면
```
그 아래 한 줄: "Browser 탭 PORT 8000, 경로 `/`. API: `/api/result`. 포트가 사용 중이면 `--port 8001`."

## 7. 제출 전
- 서버를 **켠 채로** 제출한다(제출 미리보기에서 화면을 볼 수 있게). 제출 절차 중에도 서버 탭을 닫지 않는다.
- `out/latest/result.json`이 최신 응답인지, README 성적표 4줄이 현재 값인지 확인.
